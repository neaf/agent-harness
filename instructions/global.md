# Global working rules

- Prefer semantic tools (Serena MCP, when available) over text replacement, sed, regex or Python-script edits for code navigation, renames and refactoring.
- Before reporting a code change as done, run the project's compile/test command and report the result.
- Never print, commit, or paste secrets, tokens, or credential files.
- Match the existing code style. Do not reformat files you did not otherwise need to change.
- If the project has its own `AGENTS.md`, follow it over these defaults.
- Delegate self-contained work (captures, long test runs, extraction, doc fixes) to subagents when it saves tokens or keeps the main context clear. Give each a full task spec, file ownership and the expected report format. Run independent tasks in parallel in the background.
- Do not run tests or commands after every small edit, and do not let them print long output. Trust the code, verify at larger milestones, and fix what fails. Filter output to the pass or fail line and the failing numbers.
- Write tools so their default output is minimal: one summary line or a short table, with details behind a flag.
- When work spans several sessions, subagents or PRs, keep notes in `.ai-notes/<area>/` (see the `ai-notes` skill). Read `.ai-notes/README.md` at the start of a session if it exists.
- After you push to a pull request, open one, or start a long local fix-and-test loop, arm a background watcher with the `feedback-watch` skill and react to its lines instead of checking CI, reviews or tests by hand. Keep one watcher per set of PRs and re-arm it when it expires.
- "Do it in a fork" or "with a clean context" means a fresh subagent with a self-contained prompt, not a copy of the conversation.
- Compute is free, tokens are not. Always prefer spending machine time over spending tokens. In a reverse-engineering task the user starts explicitly, when the logic of a system can be read from its binary or source, spend whatever machine time decompilation, emulation and batch extractors need to get the definitive source. Do not substitute many experiments, test runs, probe renders or long deliberation for that read. A measurement is a fallback for what the source leaves open. A measurement is fine when it is one scripted batch that runs for an hour and answers the question, in place of many small hand-driven runs.
- For external libraries, tools and services, the documented surface (docs, typings, public API, --help) is the source of truth. Do not read minified, compiled or binary internals unless the task is reverse engineering. Settle behaviour the docs leave open with one scripted check, and keep the code that depends on it in one place.
- Do not re-run the full test suite after every step. One run per step burns tokens on output Claude has already seen pass. Run it at milestones, pipe through a filter for the pass/fail line and failure count, and trust green code in between.
- When the user asks for a deliverable they will review (an artifact, report, design, asset, document), or brings up a new self-contained task while another thread is going, delegate it to a background subagent instead of doing it in the main thread, even when it looks small. Start the description with `For review: ` when the user will review the result. Write a self-contained brief, tell the user in one line that it started, then go on with the conversation. When it finishes, tell the user it's ready: what it is, where it is, how to open it, and what to look at first. Then stop for their review instead of building on it. Subagents you start for your own steps don't get the prefix.
- Before starting a task, check your available skills for one whose description fits and use it, for example `frontend-design` for visual work (UI, icons, mockups, storyboards) or a reverse-engineering skill such as REA for binaries and app behaviour. This applies to subagents too. When you delegate and know a skill fits, name it in the brief as well.
- In replies to the user, write every pull request, issue or ticket number as a markdown link to it (for example `[#123](https://github.com/<owner>/<repo>/pull/123)`), not as bare text.
